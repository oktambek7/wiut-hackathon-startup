# PolisDiff — OSAGO offer check

**Track:** FinTech / AI in Finance · **Mode:** Startup · WIUT hackathon final, team Nirvana

PolisDiff tells a buyer of Uzbek compulsory motor insurance (OSAGO), in plain words,
whether an insurer's offer matches the law, what deadlines the insurer must meet if a
claim happens, and what to do if they differ. Insurers use the same engine to check
their own offers before publishing. Every statement is tied to a quote from the PDF
(with the page highlighted) and to a dated legal source on lex.uz.

## What it does

1. **Check an offer** — upload a text PDF (Russian, Uzbek Latin/Cyrillic). Three checks run against the
   law version for the contract date you confirm: total insurance sum (40M UZS before 2026, 80M UZS
   from 2026-01-01), payment within 5 working days after the insurer's decision, decision notice within
   15 days after a claim. Four statuses only: match, potential conflict, not found, cannot verify.
2. **Claim deadlines** — enter the claim/decision date; get the legal due dates, counting Uzbek public
   holidays from [`rules/holidays.json`](rules/holidays.json) (each date sourced; unverified periods are shown as warnings).
3. **Complaint draft** — only for a confirmed conflict or a missed deadline; a deterministic template that
   quotes the offer and the provision (ru, en, uz-Latn, uz-Cyrl). Uzbek wording is an unreviewed draft.
4. **For insurers** — batch check up to 20 offers, record confirm/dismiss/escalate decisions with a reason in a
   SHA-256 hash-chained log (browser-local for now; shared database not connected).

The date is never guessed: unknown date → all checks `UNVERIFIABLE`.

## Architecture

```
web/            Next.js (App Router, TypeScript, Tailwind) — Vercel
polisdiff/      engine, rules, i18n, exports (Python)
  api_v1.py     public /v1 API: checks, localize, pages, deadlines, letters, report, catalogue
  server.py     ASGI app (CORS) used by Vercel (vercel/api/index.py) and Dockerfile.space
  deadlines.py  claim-clock + working-day calendar     letters.py  deterministic letter templates
rules/          catalogue.v1.json (dated legal rules), holidays.json
app.py          original Streamlit app (offline reference product, all features intact)
evaluation/ tests/ docs/ scripts/   benchmarks, 480+ tests, documentation
```

Nothing is stored server side: the browser keeps the PDF and report. The PDF is processed in memory.
No external AI API is called. Production design: the same container runs inside a bank perimeter, offline.

## Current deployment limits (honest)

- The public API runs on Vercel with **keyword retrieval only** and a **4 MiB** upload limit. Hybrid AI retrieval
  (multilingual E5) needs a container host: see [`Dockerfile.space`](Dockerfile.space) (written, not yet deployed).
- OCR is not available; scanned PDFs without a text layer abstain.
- Insurer review log is browser-local. No pilot or customer data exists; time-saving claims are hypotheses.
- Supported contract dates: 2024-08-05 – 2026-10-10 (catalogue verified 2026-10-10).

# Original offline app (v0.2) and evaluation


Offline multilingual evidence screening for public Uzbek OSAGO insurance offers.
Python + Streamlit + PyMuPDF + locally provisioned multilingual E5 + deterministic,
date-versioned rules. Interface and HTML reports: Russian (default), Uzbek Latin,
Uzbek Cyrillic and English. Document variants remain Uzbek Latin, Uzbek Cyrillic,
Russian and mixed passages; an English interface does not add English PDF analysis.

**Local prototype; not submission-ready.** Public deployment is deferred by the
user and must later pass an independent browser test. All engineering legal
interpretations are **PENDING_LEGAL_REVIEW**. Three checks cannot certify an
entire document. `NOT_FOUND` does not mean a violation.

### Quick start — Windows PowerShell

Run from this repository. Python 3.12 was used in the actual local run.

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.lock.txt
.venv/Scripts/python.exe scripts/download_model.py
.venv/Scripts/python.exe main.py
```

Open [localhost:8501](http://localhost:8501). The model provisioning step downloads
weights once; subsequent analysis runs offline. Pin model provisioning to the
recorded revision if creating a fresh environment:

```powershell
$env:POLISDIFF_MODEL_REVISION = '614241f622f53c4eeff9890bdc4f31cfecc418b3'
.venv/Scripts/python.exe scripts/download_model.py
```

The existing workspace `.venv` and `models/` are ready after this session's setup.
For a loopback-only local launch, use:

```powershell
.venv/Scripts/python.exe -m streamlit run app.py --server.address=127.0.0.1 --server.port=8501
```

The app honors `PORT` (default 8501) and binds `0.0.0.0`; firewall exposure is an
operator decision. `.env.example` is a reference; no dotenv autoloading or
credentials are needed. Runtime explicitly disables Hugging Face downloads.
Automatic source watching is disabled to avoid Transformers lazy-import watcher
errors; restart the server after changing application code or configuration.

### Use

Version 0.2 presents a multilingual preliminary review dashboard: a count-based
summary, plain-language finding cards, original quotations, source versions,
neutral next steps and page navigation. There is no compliance percentage or
whole-contract approval. The contract date starts **empty**; confirming the
checkbox alone does not invent a date. The audit date records when you check,
while the contract date selects the reference version. Unknown/unsupported dates
abstain before any numeric conclusion.

Choose **Language / Til / Тил / Язык** in the sidebar: **O‘zbekcha**, **Ўзбекча
(кирилл)** or **English**, alongside **Русский**. Controls, status explanations,
summaries, next steps and HTML reports follow the selection. Language switching
preserves the current document, dates, search mode, results and recorded reviews.
Clearing the session preserves the language preference; another browser session
starts in Russian. Original PDF quotations, official legal text and catalogue
version notes remain untranslated. JSON preserves the original analysis fields.

Use “Посмотреть доказательство” on a finding to open the exact PDF page and
original text directly beneath that finding. Bounding boxes are coarse unions of extraction blocks, so no
misleading visual highlight is drawn. Advanced search and technical metadata
remain collapsible; the actual mode and any lexical fallback are visible.

Analyst annotations preserve the original algorithm status. A changed document,
date or search mode invalidates the previous report and review form. Clearing the
session resets the upload and configuration. Export before clearing: records are
not a durable legal audit database.

“Скачать HTML отчет” (or its translated label) produces a self-contained report
in the selected interface language, with executive
summary, overview, findings, legal limitations, reviews and technical appendix.
Open it locally and use **Print → Save as PDF** for A4 output. JSON schema 1.0
remains readable; optional `check_scope`, `source_version_note` and
`candidate_selection` fields add provenance without renaming existing fields.

1. Upload an authorized OSAGO PDF, up to 10 MiB and 80 pages.
2. Choose the audit date and explicitly confirm the contract applicability date.
   Unknown dates produce abstention. Historical headers are hints, not authority.
3. Run hybrid AI + lexical retrieval, semantic retrieval, or the lexical baseline.
   Missing model weights cause an explicit labelled lexical fallback.
4. Review the four statuses, original Unicode quotations, actual pages,
   provision references, legal-version dates and warnings.
5. View the rasterized PDF page and extracted original text. Appendix classification
   is heuristic and always requires manual review.
6. Record confirm/dismiss/further-review with a rationale. Download JSON or HTML.
   Review data lives only in the session; export before clearing it.

Supported dates: 05.08.2024–10.10.2026. Checks: total insurance sum, indemnity
payment after the insurer's decision, decision notification after an indemnity
request. See [legal review](LEGAL_REVIEW.md) and [catalogue](rules/catalogue.v1.json).

**OCR is disabled.** Tesseract was absent and no OCR-quality metrics were produced.
Scans and damaged text result in warnings/abstention. The GROSS Latin public
sample demonstrates the current degraded-text limitation rather than a fake pass.

### Redesign and engineering audit

The subsequent language addition is documented separately in
[multilingual verification](docs/I18N_VERIFICATION.md), with fresh
[test counts](evaluation/i18n_tests.json) and
[desktop/mobile language journeys](evaluation/i18n_browser_results.json).
Earlier audit artifacts remain measurements of their recorded source snapshots.

Read [the audit report](docs/AUDIT_REPORT.md) and
[post-audit measurements](evaluation/AUDIT_RESULTS.md) for fresh commands,
confirmed defects, tests and remaining limits. The original 67-test record and
88.9% fresh accuracy / 80% conflict recall remain historical measurements.
The former fresh fixtures influenced this audit and are now explicitly regression
data, not an independent holdout. No AI accuracy advantage has been established.

The audit also rechecked the original public PDFs. INSON pages 9–66 are correctly
classified as appendices in the active extractor; the older
`real_extraction.json` is preserved as a stale historical inspection. A top-K
retrieval omission of GROSS Cyrillic page 5 was fixed by a conservative offer-topic
scan. That document's 2024 header and newer amount still need specialist date
review. Original insurer PDFs and full reports remain ignored in `local_data/`.

Browser checks now write `evaluation/audit_browser_results.json`; smoke/fallback
checks write separately named audit artifacts. Benchmark reruns default to
`evaluation/post_audit/`; use `--reports` to also write synthetic per-case reports.
They do not overwrite the original measurement files. No production deployment
is part of this audit. The existing Docker image predates these changes and has
not been rebuilt or revalidated by this audit.
